# フレーム生成（Frame Generation）の設計メモ — v28.34β 時点では **未実装**

このメモは「将来フレーム生成を入れるなら、この単一HTMLではこう作る」という案だけをまとめたものです。
v28.34β にコードは入っていません。ゲーム内では **設定 → フレーム生成 → 計画を見る** で同じ内容が読めます。

---

## 1. 何をするものか

描画したフレームとフレームのあいだに、**計算で作ったフレーム**を1枚はさみ、
表示上のなめらかさを 2 倍にする仕組みです。実際に描く回数は増えないので、
「描画が重いが、画面の書き換え（リフレッシュレート）には余裕がある」状況で効きます。

- 効く場面：ウルトラ画質＋高解像度、120Hz 以上の画面、GPU が詰まっているとき
- 効かない場面：CPU（当たり判定・AI）が原因で遅いとき、60Hz の画面、ゴミスペモード

---

## 2. 方式の比較

| 方式 | 中身 | 入力遅延 | 実装量 | 採用 |
|---|---|---|---|---|
| **A. 再投影（reprojection / space warp）** | 直前のフレームの色と深度を、予測したカメラ行列で押し出す | 増えない | 小 | ◎ 第1段階 |
| **B. 速度ベクトル（motion vector）で外挿** | ピクセルごとの移動量を別バッファに書き、半分だけ進めて色を運ぶ | 増えない | 中 | ◎ 第2段階 |
| **C. 2枚の実フレームの補間** | 次のフレームを待って中間を作る | **1フレーム増える** | 中 | × 採用しない |
| **D. ML 補間（WebGPU + 小さな CNN）** | 学習済みモデルで中間を推定 | 増えない〜小 | 大 | △ 将来 |

FPS は「見てから撃つ」ゲームなので、**遅延が増える C は不可**。
A → B の順に積み上げ、D は WebGPU が前提にできるようになってから検討します。

---

## 3. この作品での実装場所

`PostFX` がすでに「描画先（レンダーターゲット）＋全画面パス」の仕組みを持っているので、そこに足します。

```
PostFX
 ├ history[2]      … 直前2フレームの色（ピンポン）
 ├ depthRT         … 深度（再投影に使う）
 ├ velocityRT      … 速度ベクトル（RG16F, 動く物だけを描く2回目のパス）
 ├ warpPass        … 色を押し出すシェーダ
 └ fillPass        … 穴（前フレームに写っていない場所）を周囲から広げて埋める
```

### 速度ベクトルの作り方（方式B）

1. 各メッシュに `userData.prevMatrixWorld` を持たせ、`onBeforeRender` で前フレームの行列を保存する
2. 動く物（兵士・車両・自機の銃・ミサイル・無人機・F-15）だけを
   `scene.overrideMaterial = velocityMaterial` で 2 回目に描画する
3. シェーダで `uvPrev - uvCur` を書き出す
4. 地形・建物のような動かない物は **カメラの再投影（方式A）だけで足りる**ので、
   2回目の描画に含めない（描画回数を増やさないため）

### タイミング

- `requestAnimationFrame` は表示レートで呼ばれる
- 偶数回 = 実描画、奇数回 = 生成フレーム
- 実描画にかかる時間（`Afterlight.frameTime`）と表示間隔の安定度を測り、
  **表示間隔 × 2 > 実描画時間** のときだけ有効にする

## 4. 破綻させないための決め事

1. **HUD・照準・文字は生成フレームでも描き直す**（引き伸ばすと読めなくなる）
   - この作品は HUD が CSS と 2D キャンバスなので分離しやすい
2. **ワープ量に上限**を設け、超えたら生成をやめて実フレームを 2 回出す（急な振り向き対策）
3. **加算合成の物（曳光弾・爆発・SkyFX）はワープ対象外**にして、生成フレームでも軽く描き直す
4. **遠距離の深度精度**：F-15 任務は遠クリップ 120km。逆Z（reversed-Z）か対数深度にしないと再投影がにじむ
5. **iOS の浮動小数点レンダーターゲット**は対応状況を実行時に確認し、駄目なら自動で無効化

---

## 5. 設定画面に出すもの

```
フレーム生成   オフ / 2倍（再投影）/ 2倍（速度ベクトル）
               ※ 画面が120Hz以上のときに効果。HUDは常に実フレーム。
               ※ スマホは既定オフ。ゴミスペモードでは無効。
```

画質設定との関係：

| 画質 | フレーム生成 |
|---|---|
| ゴミスペ | 無効（そもそも軽い。生成の計算ぶん逆に重くなる） |
| 低 / 中 | 任意（既定オフ） |
| 高 | 任意 |
| ウルトラ | いちばん効く（解像度を上げたぶんを表示レートで取り返す） |

---

## 6. 確認のしかた（デバッグ）

- 生成フレームだけ薄い赤に着色する表示モード
- 画面に出す 3 つの数値：**実描画 fps / 表示 fps / 破棄した生成フレーム数**
- 判定：破棄率が 10% を超える、または輪郭のにじみが目視でわかる場合は自動で無効化

## 7. 段階的な進め方

| 段階 | 範囲 | 目安 |
|---|---|---|
| 1 | ムービー・リプレイ・観戦だけで再投影（方式A） | 小 |
| 2 | 対戦中にも再投影（HUD 分離・上限クランプつき） | 中 |
| 3 | 動く物の速度ベクトル（方式B） | 中〜大 |
| 4 | 設定画面に出し、自動判定で入り切り | 小 |
